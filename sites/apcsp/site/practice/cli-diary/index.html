Build a CLI diary from zero

Start with an empty Python file. Make a menu, add and list entries, save them between runs, and finally search them. Each step gives you a small behavior to test before you continue.

← Back to all handouts and practice
Use fictional entries in class. The finished program writes readable text to your own computer. It is not encrypted. Do not enter passwords, private student information, or real personal stories; do not upload the saved file to AI tools, CodeHS, or a public repository.

0. Decide what the first version must do

A command-line interface (CLI) uses the terminal for input and output. Our smallest useful diary needs four choices:

ChoiceInputProgram actionOutput
AddOne line of fictional textReject blank text; save a recordA saved message
ListNo extra inputRead saved recordsNumbered entries
SearchA wordKeep records containing that wordMatches or “no match”
QuitNo extra inputStop the menu loopA goodbye message

We will first make Add and List work only while the program is running. Losing the entries on restart will show why a file is needed.

1. Create an empty Python file

Make a folder for this exercise and create a blank file named diary.py in it. Use a local terminal with Python 3.9 or newer. From that folder, run:

python3 diary.py

An empty file exits without printing anything. That is your starting point. On Windows, use py diary.py if python3 is unavailable.

2. Build the menu loop

Type this into diary.py. Each if branch is a placeholder for one future feature.

while True:
    print("\nCLI Diary: 1 Add | 2 List | 3 Search | 4 Quit")
    choice = input("Choose 1–4: ").strip()
    if choice == "1":
        print("Add comes next.")
    elif choice == "2":
        print("List comes next.")
    elif choice == "3":
        print("Search comes next.")
    elif choice == "4":
        print("Goodbye.")
        break
    else:
        print("Choose 1, 2, 3, or 4.")

input() waits for the user. strip() removes surrounding spaces. while True keeps showing the menu, and break stops it when the user chooses Quit.

Checkpoint A

Run the file. Try 1, an invalid choice, and 4. Explain why the menu reappears after the first two choices but not after Quit.

3. Add and list entries in memory

Put entries = [] above while True. Replace only the Add and List branches with the code below; keep Search, Quit, and the invalid-choice branch.

if choice == "1":
    text = input("Write one fictional entry: ").strip()
    if text:
        entries.append(text)
        print("Entry added.")
    else:
        print("Nothing was added.")
elif choice == "2":
    if entries:
        for number, text in enumerate(entries, start=1):
            print(f"{number}. {text}")
    else:
        print("No entries yet.")

The list is the first data structure. append() adds one item; the for loop displays every item. Add two fictional sentences and list them. Then quit and restart: the list is empty because it existed only in memory.

Checkpoint B

Predict the output before testing: What happens if you choose Add and press Enter without typing text? What happens to the two entries after a restart?

4. Give each entry a time and save it to a file

Now one entry should be a dictionary with two fields: text is the content, and created_at describes when that content was added. Put these imports, paths, and helper functions above the menu loop:

import json
from datetime import datetime
from pathlib import Path

DATA_DIR = Path.home() / ".csp-diary"
DATA_FILE = DATA_DIR / "entries.jsonl"

def save_entry(text):
    entry = {
        "created_at": datetime.now().astimezone().isoformat(timespec="minutes"),
        "text": text,
    }
    DATA_DIR.mkdir(parents=True, exist_ok=True)
    with DATA_FILE.open("a", encoding="utf-8") as file:
        file.write(json.dumps(entry, ensure_ascii=False) + "\n")

def load_entries():
    if not DATA_FILE.exists():
        return []
    with DATA_FILE.open("r", encoding="utf-8") as file:
        return [json.loads(line) for line in file if line.strip()]

Remove entries = []. In Add, replace entries.append(text) with save_entry(text). Replace the List branch with:

elif choice == "2":
    entries = load_entries()
    if entries:
        for number, entry in enumerate(entries, start=1):
            print(f'{number}. [{entry["created_at"]}] {entry["text"]}')
    else:
        print("No entries yet.")

Path.home() keeps the data outside this website and your practice folder. File mode "a" appends a line without replacing older lines. json.dumps() turns a dictionary into text; json.loads() turns that text back into a dictionary. One JSON object per line is called JSON Lines.

{"created_at":"2026-09-29T10:30+08:00","text":"Today I compared two data sets."}

The time stamp is metadata: it describes the diary entry. It is useful for organizing entries, but it is not the entry's text.

Checkpoint C

Add a fictional entry, quit, restart, and choose List. The entry should still appear. Find the exact data path by reading DATA_DIR and DATA_FILE; do not copy the saved file into the website folder.

5. Add a case-insensitive search

Replace the Search placeholder with this branch. It reads the file, keeps matching records, and displays them.

elif choice == "3":
    term = input("Search word: ").strip().casefold()
    if not term:
        print("Enter a search word.")
    else:
        matches = [
            entry for entry in load_entries()
            if term in entry["text"].casefold()
        ]
        if matches:
            for number, entry in enumerate(matches, start=1):
                print(f'{number}. [{entry["created_at"]}] {entry["text"]}')
        else:
            print("No matching entries.")

casefold() makes ordinary letter-case differences irrelevant to this search. The list comprehension is a filter: it builds a new list containing only the entries that meet the condition.

Checkpoint D

Save an entry containing Python. Search for python, then for a word that is absent, then press Enter at the search prompt. Explain all three results.

6. Refactor after the behavior works

The Add and Search branches are getting long, and List and Search repeat the same display loop. Give those tasks names: add_entry(), search_entries(), and show_entries(entries). Put the menu in main(), then call main() at the bottom of the file. The behavior stays the same; the code becomes easier to read and change.

8. 如果用日记程序练习 Create / FRQ，应该怎样回答？

这里的文件名是 diary.py。AP CSP 的做法是先完成 Create Performance Task，再在考试中围绕自己的程序回答书面问题。下面用这份课堂程序示范如何寻找代码证据，所有练习情境与英文示例均为原创，不是官方题干或固定标准答案。

先了解考试流程

  1. 考前开发：学校提供至少 9 小时课堂时间完成 Create。程序需要真实使用输入、输出、管理复杂度的列表，以及带有效参数的学生自编过程；选定过程内部要包含顺序、选择和迭代，并在程序中被调用。
  2. 考前提交：在 AP Digital Portfolio 分别将完整代码 PDF、运行视频和 Personalized Project Reference（PPR）提交为 final。视频须展示输入、功能、输出，最长 1 分钟、最大 30 MB，不含身份信息或旁白；视频与 PPR 必须独立完成。完整代码需保留外部代码/AI 来源说明；PPR 只能放规定的代码截图，不能含注释、课程笔记或预写答案。
  3. 考试当天：在 Bluebook 完成 Section I：70 道选择题、120 分钟，占 70%；Section II：2 道书面题、共 4 个提示、60 分钟。Create 与书面回答合计占 30%。答书面题时可使用已按时提交为 final 的本人 PPR，不能把本教学页当作考场参考。
  4. 现场按题回答：四类是 WR1（设计、功能和目的）、WR2(a)（算法）、WR2(b)（错误与测试）、WR2(c)（数据与过程抽象）。每年问法会变；先圈出题目要求，再用自己的代码、具体数据和因果解释回应。

先选对程序证据，再写回答

就代码结构而言，现有 show_entries(entries) 是清晰的过程分析对象：参数 entries 决定输出哪些记录；先检查空列表（选择），再按顺序遍历记录（迭代），取出时间和正文并打印（顺序）。main() 中的 show_entries(load_entries()) 是一次调用。search_entries() 没有参数，不能因为它含搜索逻辑就把它当作符合 PPR 参数要求的过程。这些结构分析不代表参考代码满足学生原创要求。

练习列表证据时，可沿着 search_entries() 中的 matches = [...]（把筛选结果存入列表）与 show_entries(matches) 的调用，追踪到 show_entries 内对参数 entries 的遍历；这时二者指向同一个列表。应同时看清存储、传参和使用，不能把文件 entries.jsonl 本身叫作 Python 列表。正式 PPR 应从自己的程序中独立选择对应片段。

WR1 · Program Design, Function, and Purpose

练习方向：程序服务谁、解决什么问题？说明一个输入如何产生输出。回答要区分目的（为什么需要）与功能（程序做什么）。

英文示例：My program helps a learner save and retrieve short practice notes. The user enters a note through the terminal, and the program stores its text with a timestamp in a local file. When the user enters a search word, the program displays matching notes. This helps the learner find earlier notes without reading every saved entry manually.

代码依据：input() 接收正文/关键词；save_entry(text) 写文件；搜索用 casefold() 忽略大小写；show_entries 输出编号、时间、正文。若题目只问某一项，就聚焦该项，不必把所有功能重写一遍。

WR2(a) · Algorithm Development

练习方向：解释 show_entries(entries) 的算法，并追踪迭代次数。假定传入两条有效记录，正文依次为 Learn Python 和 Read a book。

英文示例：The procedure first checks whether entries is empty. If it is empty, it prints a message and returns. Otherwise, the for loop visits each entry once. With two entries, the loop body executes twice. On each iteration, it prints the entry number, timestamp, and text, in the original list order.

说明原因：空列表会提前返回，循环执行 0 次；非空且记录结构有效时，循环体执行 len(entries) 次。参数换成另一组记录，输出也会改变。若问无限循环，须针对自己的循环解释：当前 for 遍历有限且未被追加的列表会结束；假设把它改成没有退出条件的 while True，才会无限重复。不要把菜单中持续等待用户输入与这个列表循环混为一谈。

WR2(b) · Errors and Testing

练习方向：给出测试输入、预期结果以及它验证的行为。测试前提：使用一个只含下面两条虚构记录的练习数据文件。

测试输入 / 调用预期结果验证什么
保存 Learn Python、Read a book；搜索 python只显示 Learn Python 对应的记录大小写归一化和匹配分支
搜索 oceanNo matching entries.无匹配时的空列表路径
搜索只输入空格Enter a search word.输入检查；此时不会调用显示过程
直接调用 show_entries([])No matching entries.；随后返回选定过程的空列表分支

英文示例：With the two saved notes “Learn Python” and “Read a book”, I would search for “python”. I expect only the first note to be displayed because both the search term and each note are case-folded before the substring comparison. This checks that capitalization does not prevent a match.

如果题目问错误：把 entry["text"] 误改为 entry["body"]，在显示现有的非空记录时会产生 KeyError，因为记录只有 created_at 和 text 键；恢复正确键名可修复。空列表会提前返回，不能触发这个错误。若题目要求“过程的测试调用”，应直接给 show_entries 的具体参数及结果，而不只写菜单操作。

WR2(c) · Data and Procedural Abstraction

练习方向：指出具体列表、元素内容，以及它如何管理复杂度；再说明参数化过程如何减少重复。

英文示例：The matches list stores the diary records that satisfy the search condition. Each record contains a timestamp and text. A single loop can display any number of matching records. Without this list, using a separate variable and display statement for each match would require code changes as the number of matches grows. The show_entries(entries) procedure also lets List and Search share the same display logic; a change to the output format can be made in one place.

如果题目要求新算法：例如统计正文恰好等于目标值的记录：先把计数设为 0；逐条遍历列表；比较当前记录的 text 与目标值，相等就加 1；遍历结束后返回计数。若题目提供比较过程，就按其规格调用；不能把“正文完全相等”偷换成原程序的“包含关键词”。这是一种算法描述练习，不是现有程序已实现的功能。
