Data Compression

Compression is not automatically worse quality. It is a choice among size, transfer time, quality, and recoverability.

← Back to the Big Idea 2 handouts

Success criteria

  • Explain how compression reduces bits used for storage or transmission.
  • Compare lossless and lossy compression.
  • Explain how redundancy can affect compression results.
  • Choose a compression approach by explaining the context and priority.
lossless

Complete reconstruction

The original data can be recovered exactly. Choose it when accuracy is the highest priority.

lossy

Approximate reconstruction

It often reduces size further but removes some detail. Choose it when size or speed matters more.

redundancy

Repeated patterns

More repeated or predictable structure can allow some algorithms to reduce size more effectively.

Important: fewer bits does not automatically mean less information. The meaningful loss depends on the representation, algorithm, and purpose.
Fun fact — can gzip compare languages? Take two similar-length translations of the same passage, encode both as UTF-8, and compare the normalized gzip compression distance: (gzip(A+B) − min(gzip(A), gzip(B))) / max(gzip(A), gzip(B)). A lower value means gzip found more shared byte patterns. It is only a rough clue about patterns in these samples—not a measure of meaning or a definitive ranking of whole languages. Keep the samples, encoding, and concatenation order consistent.

Make the choice from the task

SituationPriorityReasonable choice
Saving program source codeExact recoveryLossless: one character can change a program.
Previewing a large image on limited bandwidthSmaller size and faster transferLossy may be reasonable if approximation is acceptable.
Preserving unique raw experimental dataVerifiable completenessLossless: an approximate copy cannot replace the source.

Mini-special topic: from byte compression to semantic compression

Different compression methods remove different kinds of predictability. The receiver must know the same decoding rule, dictionary, or model that the sender assumed.

ApproachWhat it exploitsCan the exact original return?Typical use
Run-length encodingRepeated adjacent valuesYesSimple repeated symbols or pixels
Dictionary codingRepeated strings or patternsYesText and general files
Entropy / predictive codingSome next symbols are more likely than othersYes, when the coded symbols are retainedModern lossless formats

Is an LLM the “ultimate” compression method?

No—not for general lossless compression. An LLM can act as a learned predictive model for language. If sender and receiver already share a model, a short prompt, summary, or set of facts may let the receiver generate a plausible long passage. That is a form of lossy semantic compression: it tries to preserve task-relevant meaning rather than every original character.

What an LLM can do well

Compress a long discussion into key decisions, constraints, and action items; infer familiar structure from shared context.

What it cannot guarantee

Exact wording, every number, source attribution, or omitted edge case. It may add a plausible but false detail.

What is not free

The model weights, version, prompt, and decoding settings are side information. A short message works only when both sides share enough context.

For exact files, code, legal text, experimental records, passwords, or answer keys, use lossless compression and integrity checks—not an LLM reconstruction. A theoretical lower bound depends on the source distribution; learned models can approximate that distribution for some text, but no single model is a universal, free, exact compressor.

Class activity: two meanings of “keep the information”

  1. Write a 120-word event notice with time, location, audience, and three details.
  2. Create a 20-word summary for a student deciding whether to attend. Which details were intentionally lost?
  3. Ask whether another student could reproduce the original notice exactly from the summary. Why not?
  4. List the minimum facts that must survive if the task is scheduling, then compare that with the facts needed for archival storage.

Original practice

  1. Design a short “character + run length” representation for AAAAABBCCCCCCDD. Why can this work well?
  2. Choose an approach for original code and for a display thumbnail. State the priority in each case.
  3. A file becomes 70% smaller but fine text edges cannot be recovered. Which uses would reject that result?
  4. Would an LLM summary be suitable for storing a raw lab record? State the requirement it fails.
